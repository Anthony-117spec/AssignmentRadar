## 1. 这是什么

AssignmentRadar 是一个常驻 Windows 托盘的小工具，用**你自己的登录 cookie**只读轮询
[学校的 Moodle 平台](https://moodle.scnu.edu.cn)，帮你解决三件事：

- **新作业提醒**：任何一门课布置了新作业，Windows 弹通知（点击直达作业页），可选推送到手机；
- **DDL 提醒**：截止前 24 小时（可配多档）弹提醒，已交的不打扰，老师改截止时间也会通知；
- **统一清单**：7×24 可查的作业总览——终端一条命令（`list`）或本地网页面板，未交/已交分列、按紧迫度排序。

它只**读取**你自己账号能看到的数据，不提交、不修改任何东西，也不碰统一身份认证的密码。

## 2. 三分钟上手

以下命令都在 CMD 里执行。**PowerShell 里要写成 `.\radar.bat <命令>`**
（PowerShell 默认不从当前目录找命令）。

### 第 1 步：安装（只需一次）

**推荐：双击项目根目录的 `一键安装.bat`**，跟着窗口走完即可——它会自动建环境、装依赖、
打开浏览器让你登录，**登录之后先问你要不要配一个长期令牌**（见 4.1 节），
然后才去读浏览器里的会话（读不到不拦），最后列出课程和作业。
结束时它会在桌面留一个 **`A-Radar`** 快捷方式（就是 AssignmentRadar，鼠标悬停能看到全名）。

> **为什么令牌排在读会话前面？** 读会话要解开浏览器加密的 cookie（新版 Chrome 还加了
> App-Bound 加密），是最容易失败的一步；而令牌通路**根本不依赖 cookie**。
> 先配令牌，后面这步失败就只意味着「没有整页截图」，不会把安装卡死。
> 反过来，如果先卡在读会话上，用户会以为整个工具用不了。

下面的手动步骤是它的等价拆解，供排查时参考：

```bat
cd /d C:\AssignmentRadar
scripts\setup.bat
```

`scripts\setup.bat` 做的事就是：检查 Python 版本 → 建 `.venv` → 装依赖（失败自动换清华镜像）。

> 完全手动等价于：
> ```bat
> cd /d C:\AssignmentRadar
> python -m venv .venv
> .venv\Scripts\pip install -r requirements.txt
> ```

### 第 2 步：录入 cookie（一条命令，免手抄）

> 已经配好令牌（4.1 节）的话，这一步**只为作业页整页截图**，可以随时再做，
> 也可以完全跳过——作业清单、DDL 提醒都不受影响。

**先在浏览器里登录平台** <https://moodle.scnu.edu.cn>（统一身份认证即可），然后：

```bat
radar.bat import --sso
```

工具会直接读你浏览器里的会话 cookie 写进配置——不用开 F12、不用找请求、也不可能贴错域。
想先看看它会写什么、暂不落盘，加 `--dry-run`；连 SSO cookie 一起收，加 `--sso`。

> 用的是哪个浏览器就读哪个（Chrome / Edge 都支持）。**Edge 正在运行时其 cookie 库会被
> 独占、读不到**，此时请用 Chrome，或先完全退出 Edge。没找到会话时会明确告诉你
> 「浏览器里没有找到可用的平台会话」，不会静默失败。
>
> **新版 Chrome（127+）可能读不到**：从 Chrome 127 起 cookie 启用了 **App-Bound 加密**
> （密文前缀 `v20`，密钥由**系统级** DPAPI 保护），`radar.bat import` 直读 cookie 库对它无解。
> 这时工具会**自动改用浏览器调试协议**再试一次，并提示你先运行一次：
>
> ```bat
> radar.bat browser login
> ```
>
> 这会打开一个**独立窗口**（用工具自己的私有配置目录，绝不碰你日常浏览器），
> 你在里面登录一次平台即可；登录成功后程序自动收好会话并写入配置，
> 之后 `radar.bat import` 就能一直正常读取。想手动复制的老办法仍然可用：`radar.bat set-cookie`（见第 10 节）。

### 第 3 步：（强烈建议）录入 SSO cookie，开启自动续期

同样先登录 <https://sso.scnu.edu.cn>（确认显示你的姓名，不是登录表单），然后：

```bat
radar.bat import --sso
```

一次把平台会话和 SSO 会话都收进配置。若只想更新 SSO，也可用老办法
`radar.bat set-cookie --sso`（F12 复制，**必须包含 `JSESSIONID`**）。

复制到"未登录状态下"的 cookie 是最常见的翻车原因——`radar.bat import` 避开了这个坑，
因为它只读浏览器里真实存在的会话。

### 第 4 步：验证

```bat
radar.bat check
```

预期输出：列出你本学期的课程和每个课的作业数量。

### 第 5 步：启动

```bat
radar.bat run        :: 托盘常驻 + 每 2 小时轮询 + 本地面板（自动打开浏览器）
radar.bat install    :: 可选：注册开机自启（后台无窗口运行）
```

完成。之后主要是全自动：SSO 保活让统一身份会话持续在线、失效会提前预警；当收到
「登录已过期」通知时，**在浏览器里重新登录平台、再跑一次 `radar.bat import` 即可**
（约 10 秒）。平台网关的自动续期「最后一公里」尚未打通（详见第 13 节已知限制），
门禁卡过期后仍需重新导入一次。

## 3. 核心概念：三把钥匙

平台的登录是分层的，理解这个你就明白为什么要两个 cookie、以及为什么**令牌才是最优解**：

| | 凭证 | 作用 | 保质期 |
|---|---|---|---|
| 门禁卡 | `moodle.scnu.edu.cn` 域（`MoodleSession` 等） | 打开平台的作业、课程页 | **短**（约 10~12 小时），网关会频繁轮换 |
| 身份证 | `sso.scnu.edu.cn` 域（`JSESSIONID` 等） | 学校统一身份认证，全校通用的登录凭证 | 中（约一天不活动就失效；浏览器里你持续在用，所以显得"几周不掉线"） |
| **令牌** | `ws_token`（平台自己发的 web service token） | **走 REST 接口读课程与作业，完全不碰 cookie** | **长**（不设到期；随时可在平台页面吊销） |

**令牌是推荐做法**，因为它把最难缠的一环拆掉了：门禁卡约 10~12 小时就死一次，死掉之后
清单就停在旧数据上（就是"数据更新于凌晨"那个现象），而 `requests` 又走不通重新登录
（网关改过入口、回调不升级票据，详见第 13 节）。令牌走的是平台自己的 API，
**会话死活与数据新鲜度就此脱钩**。配置只要一条命令，见 4.1 节。

工具每轮轮询后会主动给"身份证"续命（SSO 保活，限频每小时）；发现身份证已失效时，
会在门禁卡还活着的时候提前弹「SSO 会话已失效」预警。**配了令牌之后，门禁卡和身份证
就只剩一个用途：作业页整页截图**（那是渲染，必须真浏览器）——数据完全不再依赖它们。

## 4. 命令一览

**最快的方式：全局热键 `Ctrl+Alt+R`**（由配套启动器注册，不属于本项目）——任何时候按下都会
**弹出一个终端作业清单**窗口（看完按回车关闭）。清单**默认只读缓存、秒开**，后台刷新
由一键启动器拉起的 `radar.bat loop` 负责（见 4.4 节）；数据过期时清单会自己提示你加
`--refresh`。需要重启启动器后生效。
（原键位是 `Ctrl+Alt+A`，撞 QQ 截图快捷键，2026-10-14 改成了 `Ctrl+Alt+R`。）

统一入口是项目根目录的 `radar.bat`。**CMD 里写 `radar.bat <命令>`，PowerShell 里必须写
`.\radar.bat <命令>`**（PowerShell 默认不从当前目录找命令），在别的目录则用完整路径
`C:\AssignmentRadar\radar.bat <命令>`。下文统一以 `radar.bat …` 书写。

| 命令 | 作用 | 频率 |
|---|---|---|
| `radar.bat run` | 启动常驻：托盘 + 定时轮询 + 本地面板（默认命令） | 一次，长期运行 |
| `radar.bat run --no-panel` | 同上，但**不开网页面板**（不监听 8731，清单用 `list` 看） | 不想多一个本地端口时 |
| `radar.bat loop` | **无头**刷新循环：只轮询，不托盘/不面板/不弹窗（见 4.4 节） | 一键启动器里用 |
| `radar.bat list` | 终端作业清单：未交 / 已交 / **评分** 三栏（见[第 5 节](#5-终端作业清单list)）。**默认只读缓存、零请求、约 1.6 秒**；加 `--refresh` 现场刷新 | 随时 |
| `radar.bat check` | 验证登录，列出课程与作业数（只读，不写库不发通知） | 配置后验证一次 |
| `radar.bat once` | 手动跑一轮轮询（调试用） | 很少 |
| `radar.bat import` | **从浏览器直接读会话 cookie**（免手抄，推荐） | 过期时 |
| `radar.bat import --sso` | 同时导入平台与 SSO 会话 | 很少 |
| `radar.bat import --dry-run` | 只体检并显示将写入什么，不落盘 | 想先看看时 |
| `radar.bat import --cdp` | 强制走调试协议读私有配置目录（直读被加密拦截时） | 排障时 |
| `radar.bat browser login` | 打开**独立窗口**登录一次，会话存进工具私有目录 | 新版 Chrome 读不到时 |
| `radar.bat browser probe` | 无头读一次私有目录里的会话（诊断） | 排障时 |
| `radar.bat browser status` | 查看浏览器可执行文件与私有目录状态 | 排障时 |
| `radar.bat set-token` | **配一个长期令牌，从此不怕会话过期**（推荐，见 4.1 节） | 一次 |
| `radar.bat set-cookie` | 手动粘贴平台 cookie（老办法，仍可用） | 过期时 |
| `radar.bat set-cookie --sso` | 手动粘贴 SSO cookie | 很少 |
| `radar.bat attach` | **下载老师随作业发布的附件**，按「课程 / 作业」归档到本地 | 想要课程资料时 |
| `radar.bat attach --pending` | 只下载尚未提交的作业的附件 | 备考/补作业时 |
| `radar.bat attach --dry-run` | 只列出会下载什么，不落盘 | 想先看看时 |
| `radar.bat renew` | 手动触发一次自动续期（诊断用） | 排障时 |
| `radar.bat install` | 注册开机自启 | 一次 |
| `radar.bat uninstall` | 移除开机自启 | 不想用了 |

通用参数：`run --no-tray`（无托盘、控制台前台运行，便于看报错）、`list --no-color`（去颜色）、
`once --no-notify`（本轮不发通知）、`check --save-html`（保存脱敏首页供排查课程解析）。

**托盘图标**：绿 = 会话正常；红 = 会话过期；灰 = 尚未检查。
右键菜单：打开作业面板 / 立即轮询 / 暂停轮询 / 退出。

### 4.1 令牌通路（set-token）—— 推荐先做这一步

```bat
radar.bat set-token
```

它会**自动帮你打开令牌创建页**，然后等你在终端粘贴那一串 token。
**不需要账号密码**，约 1 分钟：

1. 页面会自己弹出来（用你**已登录平台**的那个浏览器；没弹就手动开
   `https://moodle.scnu.edu.cn/user/managetoken.php`）
2. 在「创建令牌」里填两栏，然后点保存：
   - **令牌名称**：随便写，比如 `radar`
   - **有效期**：**留空**（留空 = 一直有效；填了日期，到期令牌就作废）
   - **服务**：选**学校自建的那一项** ← 见下表（终端里会直接写出它的名字）
3. 保存后页面会显示一串字符 —— **只显示这一次**，复制它
4. 回到终端粘贴（不回显，粘完按回车）

「服务」下拉框里到底该选哪个，按这张表对：

| 下拉框里的服务 | 能不能用 | 说明 |
|---|---|---|
| **学校自建的那一项**（名字里带平台名，`set-token` 会直接告诉你叫什么） | ✅ **选这个** | 作业、成绩相关函数齐全 |
| `Attendance`、`ai_box`、`sjj` | ✅ 可作备选 | 同样是学校自建的，函数通常也够用 |
| `Moodle mobile web service` | ❌ 必定失败 | 名字最像，但被校方裁剪过，标准函数全被挡（`accessexception`） |

写完会**立刻验证一次**，并列出读到的本学期课程——选错服务当场就会告诉你，
并提示换哪一项重试。

> 不想让它自动开浏览器，加 `--no-open`；也可以直接把令牌当参数传进来
> （适合写脚本）：`radar.bat set-token --token <你的令牌>`。
>
> ⚠ 页面上已有的 `Webservice-xxxxxx` 那些**看不到值**——令牌只在创建的那一刻显示一次，
> 所以必须点「创建令牌」新建一枚，不能复用列表里现有的。

配好之后：

| | 令牌通路 | 原来的页面解析 |
|---|---|---|
| 依赖 cookie | **否** | 是（会话约 10~12 小时过期） |
| 每次轮询请求数 | 1（课程）+ 1（作业）+ 几个（提交状态） | 十几个页面 |
| 会话过期后 | **照常刷新** | 清单停在旧数据 |
| 附件归档 | **可以**（来自 API 的 `introattachments`） | 可以 |
| 作业页整页截图 | **不行**（必须真浏览器渲染） | 可以 |

**没配令牌也照常能用**：自动回退到页面解析路径，功能一个都不少。

### 4.2 作业附件归档（attach）

老师随作业发布的资料（讲义、实验指导书、素材包…）可以一键拉到本地，
**一个科目一个文件夹、每份作业再分一个子文件夹**：

```bat
radar.bat attach                    :: 归档附件 + 给每份作业截一张布置页整页图
radar.bat attach --pending          :: 只下还没交的作业的附件
radar.bat attach --course 网络      :: 只下名字含该关键词的课
radar.bat attach --force            :: 已存在的文件也重新下载/重新截图
radar.bat attach --dry-run          :: 只列出会下载什么，不落盘
radar.bat attach --no-shots         :: 只归档附件，不截图
```

归档结构（`<homework_dir>/<科目文件夹>/<作业>/`）：

```
D:/我的作业/                      ← homework_dir
├── web/                          ← 科目文件夹
│   ├── 实验三 列表渲染/
│   │   ├── _作业页截图.png          ← 布置页面整页截图
│   │   └── 示例讲义.pdf
│   └── 实验四 状态管理/
│       ├── _作业页截图.png
│       └── 实验四 要求.docx
└── db/
    └── 第1章实验 分布式系统观察与验证/
        ├── _作业页截图.png
        └── 第1章实验 ....pdf
```

**每份作业都会额外留一张布置页整页截图**，用来核对归档是否完整：

- 归档是程序替你读网页，读漏了、读错了从文件夹里看不出来；截图相当于**原件复印件**，
  和附件并排一放，一眼就知道老师发的东西是不是都下来了；
- 是**整页**截图（按内容实际高度出图，不是只截一屏），文件名 `_作业页截图.png`
  以 `_` 开头，排在文件夹最前面；
- **没有附件的作业也会截**——这样才能确认"这份确实没有附件"，而不是"程序漏下了"；
- 截图靠真实浏览器渲染，所以需要先跑一次 `radar.bat browser login`。没登录时**只提示、不报错**，
  附件归档照常完成；会话中途失效会**立即停止**，不会塞一堆登录页冒充截图。

**映射到你已有的科目文件夹。** 平台的课名（`Web 应用开发(26-27 上学期)`）通常和你
自己的文件夹名（`web`）对不上，所以在 `config.toml` 里配一张映射表，附件就会
**直接进你已建好的文件夹**，而不是另起一个名字对不上的：

```toml
homework_dir = "D:/我的作业"      # 归档根目录

[course_dirs]                        # 键可省略学期后缀，换学期也不用改
"Web 应用开发" = "web"
"数据库系统技术" = "db"
"编译原理与方法" = "编译"
"数字视觉基础" = "视觉"
"计算机网络基础" = "网络"
"分布式系统设计" = "分布式系统"
```

没配映射的课程会在归档目录下按课名自动新建文件夹，`radar.bat attach` 会**明确提醒**是哪些课。

几个要点：

- **只收老师发布的资料**。作业页上既有老师的附件，也有**你自己交上去的文件**
  （`assignsubmission_file`），后者会被自动排除——否则归档目录会被自己的作业塞满。
- **幂等**：已存在的文件直接跳过（`--force` 可强制重下）。所以随时可以重跑，
  重复运行不会产生多余请求。
- **轮询时也会自动归档**：每轮巡逻发现新作业或新附件就顺手下载（已存在的跳过），
  平时不用手动跑命令。想关掉就把 `config.toml` 的 `download_attachments_on_poll`
  改成 `false`。
- 归档目录已在 `.gitignore` 里——老师的资料属于他人版权内容，不该进版本库。

本仓库**不包含**取资料用的一次性脚本。作者自己另有一些放在 `data/`（已 gitignore）

### 4.4 无头刷新循环（radar.bat loop）—— 后台刷新的正主

```bat
radar.bat loop
```

**只轮询，不托盘、不面板、不弹窗。** 给自己的启动脚本用——如果你有一个"一键打开一堆
工具"的批处理，把 `radar.bat loop` 丢进去最合适（`RADAR_LOOP=0` 可关）。
一键启动器有自己的窗口和服务，雷达再弹一个托盘/面板只会添乱；而数据照样每两小时
刷一轮写进台账，于是 `radar.bat list` **永远有缓存可读**，打开就是秒开。

三个设计点：

- **共存**：`loop` 与 `run` 共用同一把 `data/radar.lock`——谁先起谁跑，另一个安静退出，
  不会出现"两个实例各刷各的"（项目里踩过：双实例一起跑了三个多小时，双倍轮询 + 并发写库）。
- **托盘与面板仍是 `run` 的活**：想用托盘图标和网页面板就照旧 `radar.bat run`；
  想要"打开即见上次结果"就交给 `loop`。
- **没有控制台也不崩**：pythonw 拉起时 `print` 会抛，`loop` 内部做了保护。

## 5. 终端作业清单（list）

```bat
radar.bat list
radar.bat list --refresh        REM 现场刷新一轮再展示（约半分钟）
```

**默认只读缓存：零请求、约 1.6 秒打开。** 刷新归后台循环管（`radar.bat run` 或
`radar.bat loop`，见 4.4 节），它每 2 小时把结果写进本地台账；打开清单时只读那份快照，
所以不用干等半分钟。想立刻看最新的，加 `--refresh`。

标题行浓缩了三件事：

```
📋 作业清单 · 数据更新于 2026-03-14 19:49（用时 27.2 秒 · 令牌通路）
```

- **数据更新于** = 最后一次**成功**刷新的时间，手动刷新与后台自动刷新写的是同一条
  记录，所以这一行**永远反映最近一次刷新，不论是谁触发的**；
- **括号里是这一轮实际用了多久**、走的是哪条通路——它同时解释了"这次为什么快/慢；
- 数据比两个轮询周期还旧时会显眼提示「下面是过期数据」，并告诉你可以 `--refresh`。

输出分三大区，**未交永远在前**：

```
📋 作业清单 · 数据更新于 2026-03-03 17:12（用时 27.2 秒 · 令牌通路）
未交 11（已截止 0 / 进行中 11 / 未知截止 0） · 已交 10 · 已忽略历史 7 个

❗ 未提交 · 已截止（可能还能补交，尽快确认）
  ⚠  12-30 00:00 │ 已过 … │ …

📌 未提交 · 进行中（按截止时间升序）
  🔥  03-05 00:00 │ 剩 1 天 6 小时 │ 实验4 — 分布式系统设计
      03-08 00:00 │ 剩 4 天 6 小时 │ 第三周作业 — 计算机网络基础

✅ 已提交
  ✔  02-28 00:34 │ 上机实验1 — 编译原理与方法

📊 评分（每门课最近 3 次 · 共 1 条）
  计算机网络基础
    ✔ 95.00/100   │ 03-02 15:27 │ 第三周作业
```

**排序规则（紧迫度从高到低）**：

1. 已截止但未交（最近的在前，最可能还能补交）；
2. 未截止未交（截止越早越靠前）；
3. 截止时间未知（老师可能没设置，留意课程公告）；
4. 已提交（最近交的在前）——**只显示最近 3 个**，总数在标题里。

**颜色即紧迫度**：红 `⏰` = 剩不到 24 小时；黄 `🔥` = 剩不到 72 小时；绿 = 更充裕；青 `✔` = 已提交。
重定向到文件时颜色自动去除，也可加 `--no-color`。

**判定规则**：平台对未提交的作业常常不显示确认标记，所以凡是**页面没有明确说"已提交"**
的作业都归入"未交"区——宁可多提醒，不能漏交。

**📊 评分区**：每门课列出**最近 3 次批改**（分数 / 评分于 / 作业名），刚被批改的课排在最上面。

- 数据来自平台成绩册，走**令牌通路**（见 4.1 节），所以**会话过期也照样能看**；
  没配令牌时这一区会提示你先 `radar.bat set-token`。
- **只列已批改的**——老师还没看的作业不进来，免得一堆"未评分"刷屏。
- **不含课程总分**：那是整门课的加权成绩，和"某一次作业的评分"不是一回事。
- ⚠️ **"评分人"拿不到**：平台的接口不提供这个字段，只有作业详情页上才显示。
- 老师批改得慢，所以这一区**一开始通常很短**，会随批改自动长出来。

> **默认打开只读缓存，不刷新。** 刷新交给后台循环（4.4 节），打开清单零请求、秒开；
> 想立刻看最新的加 `--refresh`。**想防止手抖连按也没问题**——读缓存本来就不打服务器。
>
> **刷新失败时清单会显示"过期数据"**，并明确告诉你原因。最常见的两种：
> ① **会话过期**——照提示跑一次 `radar.bat browser login` 即可恢复；
> ② **后台没在跑**——`radar.bat run` 停了，数据就停在最后一次成功巡逻的时刻。
> 标题里的「数据更新于 …」就是最后一次**成功**巡逻的时间，它比当前时间早很多时，
> 别拿这份清单当现在的状态。

> **刚交完却还显示"未提交"？** 先别慌，那多半只是**还没轮到复查**。
> 雷达不是每轮都翻作业详情（那对学校服务器太不礼貌），而是错峰复查：
> 临近截止（±12 小时）的作业每 **20 分钟**复查一次，其余每 **24 小时**一次。
> 最坏情况下要等一个复查周期才会变绿。想立刻确认，点进作业页看"作业状态"那一行——
> 写着"**已提交请评分**"就是交上了。
> （历史 bug 提示：2026-10-08 之前的版本会把已截止作业的提交状态**永久冻结**，
> 卡点交的作业会一直显示"未提交"。现已修复。）

## 10. Cookie 过期了怎么办

> **更好的办法：别让它过期。** 见 4.1 节——`radar.bat set-token` 配一个长期令牌之后，
> 课程与作业数据完全不再依赖 cookie，"过期"这件事就跟你无关了（只有整页截图还需要会话）。
> 下面这些是**没配令牌时**的兜底流程。

> **先看这里：大多数情况下你什么都不用做。**
>
> 平台会话大约 10~12 小时过期，而程序那条自动续期链路走不通（网关改过登录入口）。
> 但**真实浏览器能走通**——所以工具会：
>
> 1. **每隔 `browser_refresh_hours`（默认 4 小时）**，无头打开私有目录的浏览器去平台走一趟。
>    只要那边的 SSO 还活着，网关就会**静默**重新登录，新会话自动写回配置——**你一个字都不用输**；
> 2. 万一真过期了，轮询撞上之后也会**先自动补救一次**，救回来就继续，不打扰你。
>
> 只有**连 SSO 都死了**（通常超过一天没管）才需要你出手，见下面。
>
> 想关掉这个自动续期就把 `browser_refresh_hours` 改成 `0`（那就退回"过期后手动"）。
> **配了令牌（见 4.1 节）这一项会自动跳过**——会话只剩截图一个用途，不值得每轮花时间续。

**症状**：弹"会话过期"通知；面板顶部出现红色横幅；托盘图标变红；`check` 提示续期失败。

**处理（约 1 分钟）**：

```bat
radar.bat browser login
```

会弹出一个**独立窗口**（工具私有目录，不碰你日常浏览器）。在里面登录一次平台，
**登录成功后无需任何操作**——程序会自动发现、收好会话，并关掉这个窗口。

> 也可以先在自己的日常浏览器里登录平台，再跑 `radar.bat import`——它同样能读回会话
> （新版 Chrome 读不到时会自动改走调试协议，见 4.2 节）。
> **不需要 F12、不需要找请求、不可能贴错域。**

完成。面板横幅自动消失，托盘变绿，下一轮轮询照常。

<details>
<summary>想手动复制的话（老办法，仍然可用）</summary>

1. 浏览器打开平台并**确认已登录**（右上角显示你的名字）；
2. 页面上按 `F12` → 切到 **网络(Network)** 标签 → 按 `F5` 刷新页面；
3. 点请求列表里**一条发往 `moodle.scnu.edu.cn` 的文档请求**（筛选框输入 moodle，类型选
   **Doc**；注意不是 sso.scnu.edu.cn，那是 `--sso` 用的域名；也别点缓存命中的静态资源，
   那种会显示 "Provisional headers are shown"，看不到 Cookie）；
4. 右侧 **标头(Headers)** → 滚到 **请求标头(Request Headers)** → 找到 `Cookie:` 一行 →
   右键"复制值"（或手动复制冒号后的全部内容），**原样粘贴**即可；
   - 内容通常含 `MoodleSession=…`（平台会话），但也**可能只有网关的 `my_client_ticket=…`**
     ——平台整站被统一身份网关（`rump_frontend`）前置，`MoodleSession` 要等网关放行到
     Moodle 应用后才下发，所以**两种都收，不必强求出现 MoodleSession**；
   - 压根找不到 `Cookie:` 行？改用 **应用程序(Application) → 存储(Storage) → Cookie →
     `https://moodle.scnu.edu.cn`**，把该域名下的条目按 `name=value; name2=value2` 拼起来；
5. 执行 `radar.bat set-cookie`，粘贴 → 回车 → 再按一次回车（空行结束）；
   或者一条命令带参数：PowerShell 用单引号 `radar.bat set-cookie --cookie '…'`（CMD 用双引号）；
6. `radar.bat check` 确认 ✓。

</details>

**降低频率的技巧**：配置好 SSO cookie（第 2 节第 3 步）后，工具每轮轮询后会主动给
SSO 会话续命（限频每小时），发现 SSO 已失效时会提前弹「SSO 会话已失效」预警——趁
网关会话还活着时换新即可，不影响监控。门禁卡（moodle cookie）过期后的自动续期因
网关"最后一公里"未打通暂不可用，重新导入一次即可（约 10 秒）。
另外不用担心贴混：`set-cookie` 会识别 Cookie 来自哪个域并自动写入正确字段。

## 11. 常见问题 FAQ

**Q：`radar.bat import` 说"浏览器里没有找到可用的平台会话"？**
按顺序排查：
① **先看是不是新版 Chrome 的加密拦截**——若提示里带"App-Bound 加密会让 cookie 解不开"，
   说明直读被拦，运行一次 `radar.bat browser login` 在独立窗口里登录平台即可（之后就一直能读）；
② 确认**登录的是哪个浏览器**（Chrome 还是 Edge），`radar.bat import --browser Chrome` 可指定；
③ **Edge 正在运行时它的 cookie 库会被独占、读不到**——用 Chrome，或完全退出 Edge 再试；
④ 确认浏览器里能打开平台课程页（不是停在统一身份认证登录表单）。
`radar.bat import --dry-run` 会先把每个浏览器的体检结果打出来（是否可读、是否已登录），最便于定位。

**Q：`set-cookie` 提示"内容里应有 MoodleSession"，可我在浏览器里就是找不到？**
（手动复制路线才会遇到。**直接用 `radar.bat import` 可以完全跳过这个问题。**）
多半不是你的问题。平台整站由统一身份网关（`rump_frontend`）前置，**未登录态下所有
`moodle.scnu.edu.cn` 请求（连 `/?redirect=0` 和静态资源都算）都只有网关自己的
`my_client_ticket`**，`MoodleSession` 要等网关把请求真正放进 Moodle 应用后才下发。
所以：① 别去翻 `/rump_frontend/...` 这类网关请求；② 挑一条**文档(Doc)**类型、发往
`moodle.scnu.edu.cn` 的请求；③ 最稳的是 **应用程序 → Cookie → `https://moodle.scnu.edu.cn`**
逐个复制。**含不含 `MoodleSession` 都能用**，整行原样粘贴即可。

**Q：`radar.bat import` 会读走我别的网站密码吗？**
不会。它只读浏览器 cookie 库里 **`scnu.edu.cn` 相关**的 cookie，且只挑出参与身份认证的
那几个条目（`MoodleSession` / `my_client_ticket` / `JSESSIONID` 等），Matomo 统计、主题偏好
这类一律丢弃。读取是**只读**的，不会修改浏览器任何数据。详见第 12 节。

**Q：提示"无法识别"或"系统找不到指定的文件"？**

三种情况：① **PowerShell 里必须写 `.\radar.bat`**（PowerShell 默认不从当前目录找命令）；
② 目录不对——先 `cd /d C:\AssignmentRadar`（换成你实际解压的位置）；
③ 提示找不到 `python.exe`，说明 `.venv` 被删掉或搬走了——直接双击 `一键安装.bat`
重装一次环境即可（约 1 分钟，已有的配置不会被覆盖）。

**Q：check 列出的课程和"我的课程"侧边栏不一致？**
课程来源优先读侧边栏（教务系统同步的权威清单）。如果确实不对，运行
`radar.bat check --save-html`，把生成的 `data/debug_my.html`（已脱敏）发给开发者校准。

**Q：某个课的作业数量是 0，但我确定有作业？**
两种可能：① 老师把作业放在了测验/问卷等其他模块里（当前只监控"作业"类）；
② 该课在平台上还没点"自助选课"加入——`check` 会显示"未加入跳过"，去浏览器把课点开加入一次即可。

**Q：作业的提交状态显示"？"**
平台的状态表被主题精简过，未提交的作业页面上没有明确标记。工具宁可标"？"也不乱猜；
临近截止时照样会提醒你。

**Q：我明明交了作业，雷达却说"未提交"？**
两种可能，都不代表你白交了：
① **还没轮到复查**——提交状态是错峰复查的（临近截止每 20 分钟、其余每 24 小时），
   刚交完可能还没更新。点进作业页看"作业状态"那一行，写着"已提交请评分"就是交上了；
② 若超过一天还是"未提交"，那是老版本的 bug（已截止作业的状态被永久冻结），
   升级后重新跑一轮 `radar.bat once` 即可自动纠正。

**Q：有些作业截止日期是 2025-12-30 这种明显不对的？**
那是老师自己填的占位日期。如果不想看到，用 `ignore_due_before` 过滤（把它设成例如 `2026-03-01`，早于它的 historic 作业就全部静音）。

**Q：通知太多/太少？**
调整 `deadline_reminder_hours`（如 `[48]` 只提前两天提醒一次；`[24, 2]` 提前两天和两小时各一次）。
新作业通知无法关闭单独类型，但可以关掉 `toast` 只用手机推送。

**Q：面板打不开？**
端口被占用：改 `config.toml` 的 `dashboard_port` 后重启。或确认 `run` 正在运行。

**Q：托盘图标不见了？**
先 `radar.bat run --no-tray` 看控制台报错；日志在 `data/radar.log`。

**Q：开机自启没生效？**
确认执行过 `radar.bat install`；自启项是
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\AssignmentRadar.vbs`，
开机后以无窗口方式运行，检查托盘是否有图标。

**Q：轮询会不会把学校服务器搞挂 / 算不算违规？**
默认 2 小时一次、每次只请求 7 个课程页 + 少量详情页、请求间隔 1.5 秒、被限流自动退避。
这是正常个人效率工具的使用强度，且只读你自己账号的数据。

## 12. 安全与隐私

- `config.toml` 里的 cookie **等同于你的登录凭证**：拿到它的人可以直接以你的身份登录平台，
  SSO cookie 更是全校身份的"免密通行证"。**不要截图、不要发群里、不要提交到 git**（已在 .gitignore）。
- 万一泄露：去统一身份认证改密码（会踢掉所有会话），然后重新配置 cookie。
- 本工具只读你自己账号的数据，不提交、不改作业、不碰密码（SSO 自动续期用的也是 cookie，
  不是账号密码）。
- **`radar.bat import` 如何读浏览器 cookie**：Chrome/Edge 的 cookie 用 Windows 自己的 DPAPI
  加密，密钥按「当前登录用户」封装——所以只有**你本人、在你这台机器上**才解得开，也不需要
  管理员权限。工具的读取是**只读**的（SQLite 只读打开），**不会修改浏览器数据、不会碰你的
  浏览器 Profile**。它只提取 `scnu.edu.cn` 域下参与身份认证的那几个 cookie
  （`MoodleSession`、`my_client_ticket`、`JSESSIONID` 等），其余一律丢弃。
- **为什么新版 Chrome 读不到**：Chrome 127 起对 cookie 启用 **App-Bound Encryption**——
  密文前缀从 `v10` 变成 `v20`，密钥被**系统级** DPAPI 保护，普通用户权限解不开。
  这是 Chrome 的安全设计，**不要尝试提权去解**。本工具的正解是走浏览器调试协议
  （让浏览器**自己**把 cookie 明文交出来），见下一条。
- **`radar.bat browser` 用的是私有配置目录**（`data/browser_profile/`），不是你的日常浏览器。
  它绝不读取或修改你日常浏览器的任何数据，也不会关掉你正在用的窗口。
  `radar.bat browser login` 打开的窗口以 `--user-data-dir` 指向该私有目录，与你的日常浏览器隔离；
  调试协议只在**本机 127.0.0.1 的随机端口**上监听，且浏览器不对外开放，登录窗口关掉即结束。
- 本地面板只监听 `127.0.0.1`，局域网其他设备访问不到。
- 所有数据（作业记录、日志）都在本地 `data/` 目录。

## 13. 工作原理与已知限制

**数据流**：

```
config.toml（ws_token / cookie + 配置）
   ↓
轮询器（每 2 小时 ± 抖动）
   ├─【首选】令牌通路（web service REST，**不碰 cookie**）
   │    ├─ core_enrol_get_users_courses → 本学期课程
   │    │    （课名含学期后缀，或起止时间覆盖现在）
   │    ├─ mod_assign_get_assignments → 作业列表 + 截止时间 + 老师附件（introattachments）
   │    ├─ mod_assign_get_submission_status → 我的提交状态（只查复查队列）
   │    └─ 附件按「科目 / 作业」归档（已存在的跳过，正常情况零请求）
   ├─【保底】页面解析通路（令牌不可用时自动回退，功能一个不少）
   │    ├─ 我的课程侧边栏 → 本学期课程清单（学期过滤）
   │    ├─ 逐课课程页 → 作业列表（mod/assign 活动，按 cmid 幂等 diff）
   │    └─ 作业详情页 → 截止时间、提交状态、附件
   ├─ SSO 保活（成功轮询后给统一身份会话续命，限频每小时；失效提前预警）
   └─ SQLite（data/state.db）→ 通知（Toast/ntfy/Server酱）+ 面板 + list 命令
```

**已知限制**：

1. **令牌需要你自己创建一次**（`radar.bat set-token`，约 30 秒，不需要账号密码），之后长期有效、
   可随时吊销。**没配也能用**——只是退回页面解析通路，而那条路依赖的会话约 10~12 小时
   过期，过期后清单会停在旧数据上。
   > 历史记录：2026-10-07 曾逐一排除 cookie 集合、Referer/Sec-Fetch 请求头、HTTP→HTTPS
   > 双跳、回调时序等 8 组变量，确认"程序环境走不通网关回调"是服务端行为。
   > **2026-10-10 复测发现网关已不再强制认证**：`/`、`/index.php`、`/login/index.php`
   > 都由平台直接应答，cookie 里也不再出现 `my_client_ticket`。但平台的页面登录被
   > 校方装了 **ALTCHA 工作量证明 + 前端 RSA 加密**（两道都在校验密码之前），脚本化登录
   > 仍不可行——所以令牌通路才是正解，而不是去啃那道门。
2. **只监控"作业"类活动**：测验（quiz）、问卷等不监控（当初的需求范围）。想加可以提。
3. **提交状态可能有"？"**：平台主题对未提交作业不显示明确标记，见 FAQ。
4. **剩余时间反推的精度**：极少数页面没有绝对截止日期时，按"仅剩 X 天"反推，误差 ≤ 轮询间隔（2 小时）。
5. **平台页面改版**会导致解析失效——`check --save-html` 生成的脱敏页面是排查的第一手材料。

## 14. 降级与替代路径

这一节专门回答"某一步不成功，还能怎么办"。**每一条都是独立可用的**，前一条失败不会连坐。

### 14.1 启动服务

一键安装会按这个顺序建启动入口，每级失败都会告诉你走到了哪一级：

| 顺序 | 位置 | 机制 |
|---|---|---|
| 1 | 桌面 `A-Radar.lnk` | COM 创建快捷方式（悬停显示全名 AssignmentRadar） |
| 2 | 开始菜单 `A-Radar.lnk` | 同一个机制换个位置（桌面被 OneDrive 重定向、或没写桌面权限时走到这里） |
| 3 | 不建文件，直接告诉用户 | 打印三条命令：双击 `radar.bat` / `radar.bat run` / `radar.bat install` |

除此之外，**这些方式随时都能用，不依赖上面任何一级**：

```bat
radar.bat run                      :: 托盘 + 轮询 + 面板
.\radar.bat run                    :: PowerShell 里要加 .\
.venv\Scripts\python.exe radar.py run
radar.bat install                  :: 开机自启（写 Startup 目录的 VBS，另一套机制）
```

`radar.bat install` 写不进去时不会抛异常，会打印三种等价做法：
把 `radar.bat` 的快捷方式拖进 `shell:startup`、用任务计划程序指定
`pythonw.exe radar.py run`、或者干脆每次手动起。

### 14.2 配令牌

| 顺序 | 做法 | 什么时候用 |
|---|---|---|
| 1 | `radar.bat set-token` | 默认：自动打开令牌页、逐步引导、粘贴后立刻验证 |
| 2 | `radar.bat set-token --no-open` | 浏览器没自动弹出来，或不想让它弹 |
| 3 | `radar.bat set-token --token <那一串>` | 终端粘贴不方便（比如远程桌面里复制粘贴被拦） |
| 4 | 直接编辑 `config.toml` 的 `ws_token = "..."` | 连 Python 都不想跑；注意保存后要重新运行 `check` 才会生效 |
| 5 | **不配令牌，走会话通路** | 令牌怎么都配不上；代价是每 10 小时要 `import --sso` 一次 |

### 14.3 取会话

`radar.bat import --sso` → `radar.bat browser login`（独立私有窗口）→
`radar.bat set-cookie`（F12 手动复制，老办法）→
`radar.bat set-cookie --sso`（只更新 SSO 那一半）。

### 14.4 看清单与提醒

| 功能 | 首选 | 退路 |
|---|---|---|
| 看清单 | `radar.bat list` | 网页面板（仅 `run` 时开）→ `sqlite3 data\state.db` 自己查 |
| 提醒 | Windows 通知 | 手机推送（ntfy / Server酱）→ 只靠 `list` 主动查 |
| 托盘 | 托盘图标 | `run --no-tray` 前台跑 |
| 面板 | `run` 自带 | `run --no-panel` 不开端口 |
